# Relecture B — Expérience d'édition et code d'interface (Atelier, 30/10/2026)

Périmètre : `editor/` (app, store, canvas, dnd, inline/richedit, inspector/styletab/fields, navigator, library, templates, pages, panels, cmdk, ctxmenu, tooltip, panel-resize, actions, images, new-site-ui, help, ui-lang, editor.css) et `index.html`. Lecture du code + mesures dans Chromium (Playwright, axe-core 4.10) sur le site d'exemple MAB et sur un site enrichi de photos. Scripts et captures : `scratchpad/audit/b-*.mjs`, `b-*.png`, `b-measures.json`, `b-cost.json`.

## 1. Résumé

L'architecture d'édition est saine : un état immuable, un seul point d'entrée `commit()`, un historique qui fusionne les frappes, un canevas en iframe mis à jour sans rechargement, une logique de dépôt testable dans `core/editing.js`, un journal partout. Deux défauts sont **bloquants pour un non-informaticien** : (1) dès qu'un site contient une dizaine de photos, chaque frappe coûte ~200 ms et l'historique d'annulation copie tout le site, images comprises (1 Go de mémoire après 150 modifications : plantage probable de l'onglet) ; (2) sur un ordinateur portable courant (1366 × 768), la page est affichée à 56 % : le texte courant fait 7,6 px, illisible pour écrire « dans la page ». Viennent ensuite des manques d'ergonomie classiques face à Webflow, Framer, Wix Studio ou Elementor : dépôt refusé en silence sur une page vide, pas de listes à puces dans le texte, réglages d'espacement en CSS brut (« 0.85rem », « palette:c1 »), barre du haut en émojis, boîtes natives `prompt()/confirm()`. Le code d'interface est dense (7 % des lignes dépassent 200 caractères, 19 fenêtres construites à la main) mais cohérent et sans dépendance.

## 2. Points positifs (fichier:ligne)

- **État et historique** : `editor/store.js:89-107` — un seul `commit()`, snapshot avant modification, fusion des frappes rapides par clé (`opts.key`, 1,5 s ou `sticky`), historique borné à 150 ; `store.js:111-122` — les modifications reçues d'un autre participant sont rejouées dans le passé et le futur, donc « annuler » ne retire que ses propres changements (rare dans les éditeurs collaboratifs). Lecture seule respectée au niveau du store (`:90`).
- **Enregistrement automatique** : `store.js:64-82` — différé de 600 ms, statut « Modifié / Enregistré / Non enregistré » (`aria-live`, `index.html:56`), reprise signalée après un échec (`storage.save-recovered`).
- **Canevas** : `editor/canvas.js:167-194` — mise à jour sans rechargement (CSS échangée, en-tête/contenu/pied remplacés) ; pendant une saisie dans la page, seule la CSS change (le curseur n'est jamais perdu) ; une modification distante est mise en attente tant qu'on écrit (`:181-183`, `:252`). Prêt dès le DOM, sans attendre les polices (`:124-139`) ; mémoire du défilement par page/langue (`:224`, `:304-307`) ; calques enfichables pour la présence et les commentaires, isolés en cas d'erreur (`:356-362`).
- **Glisser-déposer** : logique pure et testée dans `core/editing.js` (`dropContainer`, `dropIndex`, `isNoopDrop`) ; géométrie corrigée de l'échelle du canevas (`editor/dnd.js:25-30`, `:107-110`) ; indicateur de dépôt horizontal/vertical/« dans » (`:159-192`) ; défilement automatique (`:151-157`) ; dépôt dans le panneau Structure ; annulation par Échap et `pointercancel` (`:280-282`) ; seuil de 5 px avant de glisser (`:16`, `:75`) ; `touch-action:none` sur les éléments de bibliothèque (`editor.css:77`).
- **Édition directe** : `editor/richedit.js` sans `execCommand`, assainissement à chaque saisie (`:130`), collage forcé en texte brut (`:133-141`), dépôt de fichier bloqué (`:142`) ; `editor/inline.js:198-223` — corrections de l'IA appliquées position par position en gardant la mise en forme ; proposition stale ignorée si la session a changé (`:278`, `:286`) ; une seule étape d'annulation par session d'édition (`:116`).
- **Inspecteur** : champs dérivés du registre des widgets (`inspector.js:124-158`), liaison aux champs d'une collection (`:104-114`), fil d'Ariane cliquable (`:37-53`), focus et défilement conservés lors du redessin (`:242-258`) ; **badge de contraste WCAG en direct** (`styletab.js:192-211`) ; recherche de réglage sans reconstruire l'onglet (`:327-343`) ; presets avec compteur d'utilisation et « par défaut pour les … » (`:279-324`) ; vue trois appareils côte à côte (`:250-256`) ; jetons d'échelle (`:160-174`) ; valeurs héritées affichées en espace réservé (`:145-146`).
- **Clavier** : flèches = parcours de l'arbre, Alt+↑↓ = déplacer, Ctrl+D, Suppr, Échap = parent, Entrée = écrire, F1, « ? » (`app.js:115-149`) ; arbre Structure entièrement au clavier avec `role=tree`, `aria-level`, Début/Fin (`navigator.js:58-83`) ; menu contextuel `role=menu` + flèches (`ctxmenu.js:70-79`) ; barre Ctrl+K qui expose toutes les actions.
- **Accessibilité de base** : `role=tablist/tab`, `aria-selected`, `aria-pressed`, `aria-label` sur les boutons-icônes, `focus-visible` (`editor.css:17`), `prefers-reduced-motion` (`:620`), mode sombre (`:8`), `<dialog>` modales avec `aria-labelledby`. axe-core sur l'onglet Style et sur la fenêtre Publier : **0 violation**.
- **Images** : conversion WebP + variantes 480/960 dans le navigateur (`editor/images.js`), avertissements pondérés (fichier lourd, résultat lourd) ; stockage IndexedDB qui sépare les images du projet (`storage.js:44-57`).
- **Journal** : chaque interaction est tracée avec un niveau adapté (trace pour la frappe, debug pour les clics, warn pour les refus) : support à distance possible sans écran partagé.
- **Démarrage** : prêt en ~0,8 s en local (FR : 89 requêtes, 1,23 Mo ; JA : +307 Ko de catalogue), aucune dépendance d'exécution, aucun outil de build.

## 3. Points négatifs

### Bloquant

**B1 — Un site avec des photos devient lent, puis fait planter l'onglet.**
Preuve : `core/site.js:146-152` (`withPage` → `structuredClone(site)`, images en base64 comprises), `core/tree.js:157-163` (`update` → `structuredClone(root)`), `editor/store.js:96` (chaque étape d'historique garde une copie complète du site), `core/render.js:57` (le canevas reçoit les images en `data:`, donc le HTML régénéré à chaque frappe pèse plusieurs Mo). Mesures (`b-cost.json`, `b-mem.mjs`) :

| Site | JSON | coût d'une frappe | rendu canevas | mémoire JS après 150 modifications |
|---|---|---|---|---|
| exemple MAB, 0 photo | 12 Ko | 7–16 ms | 3–6 ms | — |
| + 3 photos (494 Ko chacune) | 2,0 Mo | 54–77 ms | 33–53 ms | — |
| + 10 photos | 6,6 Mo | 172–230 ms | 95–182 ms | **1 033 Mo** (RSS Chromium 1,6 Go) |

Taper 10 caractères dans un titre avec 10 photos prend 1,8 s ; 40 modifications déclenchent `perf.longtask 7818 ms` (interface figée). Impact : le site touristique de Kumakōgen (15 photos et plus) sera pénible à écrire et finira par un « Aïe, aïe, aïe » de Chrome après une séance de travail ; Laurent perdra la session (l'enregistrement différé de 600 ms limite la perte, mais pas le plantage).
Correction : sortir les binaires du document immuable (un magasin d'images `id → Blob/objectURL` à côté du site, déjà préfiguré par `storage.js:44-57`), rendre le canevas avec des `blob:`/`objectURL` au lieu de `data:`, remplacer `structuredClone` par une copie de chemin (structural sharing) ou au minimum exclure `assets` de la copie et de l'historique, borner l'historique en octets.

**B2 — La page est illisible sur un portable : le canevas est réduit à 49–62 %.**
Preuve : `editor/canvas.js:378` (`DEVICE_WIDTH.desktop = 1280`) et `:389-395` (`target = max(1280, largeur disponible)` puis `scale`), `b-scale.mjs` :

| Écran | échelle du canevas | texte courant affiché | barre du haut |
|---|---|---|---|
| 1280 × 720 | 49 % | 6,7 px | 86 px (2 lignes) |
| 1366 × 768 (portable Windows le plus courant) | 56 % | 7,6 px | 86 px |
| 1440 × 900 (MacBook Air) | 62 % | 8,4 px | 86 px |
| 1920 × 1080 | 99 % | 13,5 px | 48 px |

Capture `b-editor-1024.png` : à 1024 px la page est à 35 %. Impact : « écrire directement dans la page » (double-clic) se fait sur du texte de 7 px ; un non-informaticien zoomera le navigateur et cassera la mise en page de l'éditeur. Webflow et Framer offrent un zoom et des panneaux escamotables ; Elementor et Wix rendent la page à la largeur disponible. Correction : en mode « ordinateur », rendre la page à la largeur disponible (le site publié est fluide, largeur de contenu 1160 px max) tant qu'elle dépasse ~960 px, et ne réduire qu'en dessous ; ajouter un zoom (ajuster / 100 %) et un bouton qui replie les deux panneaux ; mettre la barre du haut sur une ligne (voir I5).

### Important

**I1 — Déposer un widget sur une page vide ne fait rien, sans un mot.** `dnd.js:214-219` : refus journalisé (`dnd.refused:forbidden`), aucun toast, aucun curseur « interdit », le fantôme garde son aspect (`editor.css:205`, pas d'état refusé). Alors que le clic sur le même widget réussit (enveloppe automatique, `core/editing.js:66-70`) et que le panneau dit « glissez dans la page » (`library.js:57`). Vérifié : `b-drag-empty.png`, `b-measures.json → dropOnEmpty`. Le dépôt sur la marge d'une section existante fonctionne (`b-drop2.mjs`), le piège est donc exactement la première action après « Nouveau site vide ». Correction : même enveloppe automatique au dépôt sur la page ; état « interdit » du fantôme + toast explicite quand un dépôt est refusé.

**I2 — Pas de listes à puces ni numérotées dans un texte.** Barre flottante : gras, italique, souligné, lien, effacer, ✨ (`inline.js:49-59`) ; barre de l'inspecteur identique (`fields.js:94`) ; l'assainisseur accepte pourtant `ul/ol/li` (`core/sanitize.js:8`), mais rien ne permet de les créer, et le collage est forcé en texte brut (`richedit.js:133-141`) donc une liste collée depuis Word perd ses puces. Pas de niveau de titre ni d'alignement dans la barre. Un non-informaticien ne peut pas faire une énumération dans un paragraphe (seule issue : le widget « Liste à icônes »). Correction : boutons liste/numérotée, raccourcis « - » et « 1. » en début de ligne, Entrée dans un `li`, collage qui passe par l'assainisseur (balises autorisées gardées) au lieu du texte brut.

**I3 — Les réglages de style parlent CSS.** `styletab.js:142-157` : longueurs en texte libre (« ex. 24px »), valeurs affichées « 0.85rem », « 0.1em », couleur « palette:c1 » (`b-editor-dark.png`), erreur après coup par toast « Exemples : 24px, 1.5rem, 50%, auto, clamp(…) » (`:111`). Espacement : 8 cases « — » + 8 sélecteurs « ⇕ » (`b-style-spacing.png`), ni curseur, ni liaison des quatre côtés, ni schéma de boîte, ni poignée dans la page. 38 réglages en 7 groupes, c'est raisonnable, mais la saisie est celle d'un développeur. Référence : Webflow et Framer (poignées de marge dans la page, pas-à-pas avec unité), Elementor et Divi (curseurs, cadenas « lier les côtés », noms de couleurs). Correction : champ nombre + unité (px par défaut), bouton « lier les 4 côtés », noms de palette (« Couleur principale ») à la place de `palette:c1`, curseurs pour opacité/arrondi, puis poignées de marge dans le canevas.

**I4 — Chaque frappe régénère toute la page et reconstruit l'inspecteur.** `canvas.js:172-191` : `renderPage` complet + `DOMParser` + remplacement de `header/main/footer` à chaque `doc` (21 rendus pour 20 caractères dans un champ de l'inspecteur) ; `inspector.js:272` : l'inspecteur est reconstruit à chaque frappe dans la page (24 reconstructions pour 20 caractères, `b-measures.json`). Sur le site d'exemple c'est invisible (3–6 ms et 4–5 ms), mais le coût croît avec la taille de la page et explose avec les images (B1) ; le remplacement de `main` ré-décode les images et perd l'état du DOM (accordéon ouvert, vidéo, position d'un carrousel). Correction : rendu ciblé du nœud modifié (`renderNode(id)` + `replaceWith`), inspecteur qui ne met à jour que la valeur du champ quand la source est la frappe dans la page.

**I5 — Barre du haut : émojis sans libellé, deux lignes sous 1920 px.** `index.html:46-58` : ✨ 👥 💬 ❓ 🐞 n'ont qu'une infobulle ; ↶ ↷ ⧉ ✕ ↰ 🖌 📋 dans l'inspecteur (`inspector.js:48-52`). Les émojis se dessinent différemment selon le système (Windows, macOS, Linux) et ne disent rien à un non-informaticien ; la barre passe à 86 px (deux lignes) dès 1536 px de large (`b-scale.mjs`). Correction : icônes SVG monochromes avec libellé pour les actions principales, regroupement « Outils » (SEO, IA, À plusieurs, Commentaires) dans un menu, ordre par fréquence d'usage ; test de non-débordement à 1280 px.

**I6 — Seize `prompt()` / `confirm()` natifs.** `pages.js:99`, `:194`, `actions.js:191`, `fields.js:91` (adresse d'un lien par `prompt`, alors que la barre flottante a un vrai champ), `templates.js:55`, `app.js:223`… Fenêtres bloquantes, non stylées, non traduites par le navigateur (le texte l'est, pas les boutons), inutilisables dans un test sans crochet. Correction : `confirmDialog()` et `askText()` dans `dom.js` bâtis sur `<dialog>`, mêmes libellés et clavier partout.

**I7 — Dix-neuf fenêtres construites à la main.** `grep "h('dialog'"` : 19 occurrences dans 16 fichiers, chacune recopiant en-tête (`audit__head`), bouton ✕, pied, `showModal()`, `close → remove()` (`versions-ui.js:117-126`, `collections-ui.js:97-108`, `pages.js:218-239`, `new-site-ui.js`…). Comportements divergents (certaines fenêtres gardent le DOM, d'autres le détruisent ; retour du focus non géré). Correction : `openDialog({ id, title, body, actions, onClose })` unique, testé une fois.

**I8 — Densité du code et absence de types.** 652 lignes sur 9 922 (7 %) dépassent 200 caractères ; `styletab.js` ligne de 694 caractères, `collections-ui.js` 13 lignes > 400 ; chaînes `try { … } catch (e) { log.warn(…) ; toast(…) }` recopiées des dizaines de fois (`fields.js:191-194`, `pages.js:17-23`, `templates.js:27-30`, `actions.js:11-13`). Pas de JSDoc ni de types : le repreneur de Laurent (après le projet à 4 000 €) lira difficilement. Correction : formatage automatique (largeur 120), helper `refuse(code, message, data)` partagé, JSDoc sur les fonctions exportées de `editor/`.

**I9 — Accessibilité de l'éditeur : cinq violations axe et des onglets sans flèches.** axe-core (WCAG 2.2 AA + bonnes pratiques, hors canevas) : `aria-allowed-attr` (critique) sur `#frame` — le sélecteur `[data-device]` de `app.js:85` et `:192` attrape aussi le cadre du canevas (`data-device="desktop"`), qui reçoit `aria-pressed` et un gestionnaire de clic ; `aria-prohibited-attr` sur `#peers` (`aria-label` sur un `div` sans rôle, `index.html:51`) ; pas de `<main>` ni de `<h1>` ; poignées de redimensionnement hors de tout repère. Les onglets `role=tab` ne réagissent pas aux flèches (`b-measures.json → tablistArrowKeys`), contrairement au motif APG. Les éléments du canevas ne sont pas focalisables (`nodesFocusable: 0/30`) : la sélection au clavier passe obligatoirement par le panneau Structure (c'est documenté, mais à dire dans le guide). Correction : `role="group"` sur `#peers`, `<main>` autour de la scène, `h1` visuellement caché, flèches sur les deux barres d'onglets, sélecteur `.seg[data-device]`.

**I10 — Premiers pas : une page vide et des conseils, pas de modèle de site.** « Nouveau site vide » donne une page avec un seul espace réservé (`b-empty-site.png`) ; les conseils de l'inspecteur sont bons (`inspector.js:219-228`) mais il n'existe ni modèle de site complet (3–5 pages typées), ni liste de premiers pas, ni visite guidée (prévue au cycle 25). Correction : modèles de site (association, commerce, tourisme) + visite guidée + liste « Pour commencer » dans le panneau de gauche.

### Mineur

- **M1 — 87 modules au démarrage** (1,18 Mo de JS non compressé, +307 Ko en japonais), catalogue injecté par `document.write` (`index.html:16`). Rapide en local (0,8 s) ; sur un hébergement mutualisé en HTTP/1.1 sans compression, compter plusieurs secondes. `rel="modulepreload"` sur le chemin critique, ou un bundle de déploiement (le développement reste sans build).
- **M2 — Ctrl+S télécharge un fichier .json** (`app.js:121`) : un non-informaticien qui « sauve » par réflexe reçoit un téléchargement alors que tout est déjà enregistré. Préférer un toast « Déjà enregistré » et garder l'export dans Fichier.
- **M3 — Suppression sans retour** : `deleteSelected` ne montre un toast qu'en sélection multiple (`actions.js:81` vs `:87-96`) ; Retour arrière supprime un bloc entier quand on n'est pas en édition (`app.js:143`). Toast « Supprimé : Titre — Ctrl+Z ».
- **M4 — Barre de mise en forme** : boutons de 26 px, peut chevaucher la barre de l'élément sélectionné au-dessus (`b-inline-toolbar.png`) ; le menu ✨ est caché derrière une icône sans libellé.
- **M5 — Tablette** : les éléments du canevas n'ont pas de `touch-action: none` ; sur iPad, glisser un élément sélectionné risque d'être annulé par le défilement (`dnd.js:280`). Non testé sur appareil.
- **M6 — Nom du site tronqué** dans la barre dès 1440 px (`site-name` 220 px) ; détail.
- **M7 — Libellés tronqués** dans l'inspecteur (« Espacement des le… », « Espacement de… ») sur l'onglet Style à 330 px (`b-editor-1024.png`, `b-editor-dark.png`).
- **M8 — Onglet Avancé** : « Classes CSS » et « CSS personnalisée (experts) » visibles pour tous ; à replier derrière un « Mode expert ».
- **M9 — `window.__atelier = Object.assign(state, …)`** (`app.js:284`) expose l'état mutable ; pratique pour les tests, à documenter comme API de test seulement.

## 4. Mesures faites

- Démarrage (Chromium headless, serveur local) : FR prêt en 791 ms, 89 requêtes (87 scripts, 1 CSS, 1 HTML), 1 232 476 octets ; JA prêt en 759 ms, 90 requêtes, 1 539 980 octets (`i18n/ja.js` 307 504). Aucune erreur JS.
- Rendus par action (site d'exemple) : clic sur un onglet de gauche → 0 rendu canevas ; sélection → 1 `inspector.render` (4 ms) ; changement d'appareil → 1 `canvas.render` (3 ms) + 1 inspecteur ; onglet Style → 57 ms (contraste + 38 réglages) ; réglage de marge → 1 rendu canevas (4 ms) + inspecteur 22 ms ; 20 caractères dans un champ de l'inspecteur → 21 `store.commit` + 21 `canvas.render` (4,5 ms de moyenne, 8 max) ; 20 caractères dans la page → 21 commits, 22 rendus canevas (3,6 ms), **24 reconstructions de l'inspecteur** (5 ms) ; annuler ×3 → 3 rendus + 6 inspecteurs ; changement de page → 1 rechargement complet (`canvas.load`).
- Coût par frappe et mémoire selon les photos : tableau en B1 (`b-cost.json`, `b-mem.mjs` : heap JS 10 Mo → 450 Mo après 50 modifications → 1 033 Mo après 150).
- Échelle du canevas par écran : tableau en B2.
- axe-core : interface complète hors canevas → 5 violations (1 critique, 1 sérieuse, 3 modérées, détail en I9) ; onglet Style → 0 ; fenêtre Publier → 0.
- Clavier : ordre de tabulation cohérent (barre du haut → onglets de gauche → recherche → bibliothèque) ; flèches sans effet sur les onglets ; 0 élément focalisable sur 30 dans le canevas.
- Débordement horizontal : aucun à 900, 1024, 1280 (JA), 1440 ; note « écran d'au moins 1024 px » affichée à 900.
- Dépôt : page vide → refusé sans retour ; marge d'une section → accepté ; bord droit d'une section → accepté ; structure 2 colonnes → acceptée.
