# Cycle 31 — Données en sécurité

## Spécification
- **S6 — Stockage fiable**
  - `navigator.storage.persist()` demandé au **premier enregistrement déclenché par un geste** (clic, touche ; `navigator.userActivation.isActive`), jamais au chargement ; résultat et `estimate()` dans l'onglet Site (« Stockage : persistant · 42 Mo utilisés sur 2 Go ») et dans le journal (`storage.persist`, `storage.estimate`).
  - `beforeunload` quand l'état est « Modifié » ou « Non enregistré » (`storage.unload-warn`).
  - Ramasse-miettes des images orphelines (ni dans un projet rangé, ni dans l'état en mémoire, ni dans une version gardée) après chaque élagage de versions et sur demande (Versions → « Nettoyer les images inutilisées ») ; fonction pure `orphanAssets(siteIds, versionIds, storedIds)` dans `core/storage-gc.js`, écrite contre le magasin IndexedDB (`collectOrphanAssets` dans `editor/storage.js`) ; journal `storage.gc` (nombre, octets, source).
  - Import `.json` refusé au-delà de 200 Mo **avant lecture** (`project.import-too-big`) ; `JSON.parse` et la validation restent dans le `try` (message « Fichier illisible »).
  - Base pleine (`QuotaExceededError`) : message clair avec conseil (exporter, supprimer des versions, nettoyer les images), `storage.quota`.
- **S7a — Dossier local** (File System Access, Chrome/Edge) : Fichier → « Enregistrer aussi dans un dossier de mon ordinateur… » → `showDirectoryPicker()` ; handle gardé dans IndexedDB (magasin des secrets de l'appareil), permission revérifiée au démarrage (`queryPermission`) et redemandée d'un clic (`requestPermission`) ; à chaque enregistrement réussi, au plus une fois par 5 s : `<nom-du-site>.atelier.json` (export autonome, images comprises) + `versions/<AAAA-MM-JJ>.json` une fois par jour ; état « Copie : il y a 2 min » dans la barre ; journal `backup.folder.*`. Repli Firefox/Safari : la commande propose l'export classique ; rappel hebdomadaire non bloquant « exporte une copie » avec la date du dernier export (retenue sur l'appareil) ; journal `backup.remind`.
- **S7b — Sauvegarde chiffrée sur l'hébergement** : dans la fenêtre Publier (onglet OVH), « Copie de secours sur l'hébergement » (activable, réglage gardé dans le projet : `publish.backup`) ; à chaque publication et sur demande, `POST publish.php?backup` avec le jeton → `atelier-data/backup-AAAAMMJJ-HHMM.json.enc` ; AES-GCM 256, clé dérivée par PBKDF2-SHA-256 (310 000 itérations) d'un code de secours (8 caractères au moins) ; sel et IV aléatoires dans l'en-tête du fichier, en-tête authentifié (données associées) ; le serveur ne voit ni le code ni le contenu ; 5 dernières gardées (rotation côté serveur) ; `GET ?backups` et `GET ?backup=<nom>` avec le jeton ; restauration (jeton + code → téléchargement, déchiffrement, nettoyage des textes, validation, version de sécurité, chargement) ; 100 Mo au plus ; tout le chiffrement dans `core/backup.js` (WebCrypto, Node 22 compris). publish.php passe en **version 6** (mécanisme du cycle 29 : `PUBLISH_VERSION`, statut `backup: true`, message de mise à jour).

## Limites et décisions
- **Chromium sans interface refuse toujours `persist()`** (profil éphémère) : le scénario remplace `navigator.storage.persist/persisted` par une version qui n'accorde le stockage que pendant un geste, comme Chrome pour un site fréquenté. Le vrai comportement dépend du navigateur (Chrome : engagement, favori ; Firefox : question ; Safari : rarement).
- **Perte maximale = une modification** seulement avec la copie dans un dossier (Chrome/Edge, toutes les 5 s au plus) ; la copie sur l'hébergement suit les publications et les demandes, comme demandé (pas à chaque modification, pour ne pas épuiser la rotation de 5).
- Le rappel hebdomadaire s'affiche aussi dans Chrome quand aucune copie dans un dossier n'est active (décision prise : même risque) ; il est muet sous pilotage de test sauf avec `?remind`.
- Le code de secours n'est jamais dans le projet ; « se souvenir » le garde sur l'appareil par adresse de publish.php (comme le jeton). Le réglage « copie à chaque publication » est, lui, dans le projet.
- La fenêtre de restauration reste dans l'onglet OVH de Publier (et Ctrl+K) ; elle redemande la confirmation de destination du cycle 25 avant d'envoyer le jeton.
- `php -S` ignore les `.htaccess` : le test vérifie que `atelier-data/.htaccess` ferme le dossier ; sur OVH (Apache) il est servi en 403. Le contenu est de toute façon chiffré.
- Ramasse-miettes : écrit contre le magasin `assets` actuel. Si le cycle 27 range les images autrement (autre magasin, Blob), il suffit d'adapter `referencedAssets`/`collectOrphanAssets` dans `editor/storage.js` (la taille accepte déjà les Blob) ; `orphanAssets` ne change pas.
- La barre du haut s'allonge de « Copie : il y a 2 min » quand la copie est active (la barre débordait déjà de sa largeur à 1440 px avant ce cycle : à revoir avec le cycle 33).
- `formatBytes` écrit les décimales à la française (« 1,5 Go ») dans les trois langues.
- Régression hors périmètre, constatée sur cette branche et indépendante du cycle : `cycle20` (section « polices Google lentes » : plus aucune requête vers Google depuis le cycle 29), `cycle25` (Ctrl+S ne télécharge plus depuis le cycle 26), `cycle26` (la démonstration attend le réglage « reveal » caché en mode simple depuis le cycle 30). `cycle20` : le faux publish.php annonce maintenant la version courante (l'auto-test passe à 25 / 25).
